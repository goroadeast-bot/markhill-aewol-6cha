# 타입&가격 섹션 — 스펙

## 배경

브라우저 목업으로 확인해 확정한 내용(2026-08-22). 개요/입지 섹션과 달리 이 섹션은 **표 내용을 절대 바꾸지 않는다**는 제약이 명확히 확인됨 — 사용자가 목업 중 표가 축약된 것을 보고 즉시 지적, 전체 9행으로 복원 후 재확인받음.

## 변경 1 — 타이틀만 애니메이션

`<p class="eyebrow">타입 &amp; 가격</p>`와 `<h2 class="section-title">84A-1 · 84A-2 · 84B</h2>`만 `<div class="types-intro">`로 감싸 개요 섹션과 같은 블러+상승 등장(반복, `cubic-bezier(0.23,1,0.32,1)`, 0.7s)을 적용한다. **표 2개(`area-table`, `price-table`)는 애니메이션 없이 정적으로 표시** — 로드/스크롤과 무관하게 항상 보이는 상태.

## 변경 2 — 표 내용은 절대 변경 금지, 첫 열만 볼드

`area-table`(타입 열: 84A-1/84A-2/84B)과 `price-table`(동 열: 101동/102동/102동 근생)의 **첫 번째 열만** 볼드 + 진한 잉크색으로 강조한다. **마크업(각 셀의 텍스트, `<tr>`/`<td>` 구조, class 속성)은 전혀 건드리지 않는다** — CSS `:first-child` 선택자만으로 구현해, 기존 `tests/content.test.mjs`의 정확한 `<td>${dong}</td>` 매칭 테스트를 깨지 않는다.

```css
.area-table td:first-child, .price-table td:first-child { font-weight: 700; color: var(--ink); }
```

계약(평)/대지(평) 등 다른 열은 볼드 처리하지 않는다(이전 안에서 시도했다가 제외됨).

## 변경 3 — 계약조건/이벤트 강조 + 스윕 애니메이션

`.terms-block` 안의 핵심 수치·문구에 포인트색 하이라이트를 넣고, 스크롤로 보이면 형광펜으로 긋듯 왼쪽에서 오른쪽으로 배경이 채워지는 애니메이션(`background-size: 0% → 100%`, 0.6s, 160ms 간격 순차, 반복)을 적용한다.

강조 대상 4곳:
1. 계약조건의 `5%`(계약)
2. 계약조건의 `5%`(계약 1개월 후)
3. 계약조건의 `90%`(소유권이전시)
4. 이벤트의 `무상 제공`

수치(`5%`, `5%`, `90%`) 자체는 포인트색(`--accent`) 텍스트로, 나머지 하이라이트된 글자(괄호 안 설명, "무상 제공")는 진한 잉크색 볼드로 — 배경은 4곳 모두 동일한 저투명도 포인트색.

## 반응형 / 접근성

`prefers-reduced-motion: reduce`에서는 타이틀이 즉시 보이는 상태, 하이라이트 배경도 즉시 100% 채워진 상태(스윕 없이). 전역 규칙만으로는 초기 상태(`opacity:0`, `background-size:0%`)가 가려지지 않으므로 전용 오버라이드 필요 — **개요/입지 섹션에서 실제로 겪었던 소스 순서 버그를 반복하지 않도록, 오버라이드는 반드시 해당 base 규칙 바로 다음에 위치시킨다.**

## 스코프 밖

- 표 내용(숫자, 문구, 행 순서, 셀 구조) — 절대 변경 금지, 이번 스펙 전체에서 손대지 않음.
- 계약(평)/대지(평) 열 볼드 — 시도 후 제외.
- 다른 섹션에 같은 스윕 하이라이트 패턴 적용 — 이번엔 타입&가격 섹션 한정.

## 테스트

- `tests/content.test.mjs`: `.types-intro`가 eyebrow+title만 감싸는지, 표 내용은 기존 테스트(`'types & pricing chapter carries...'`, `'price table rows carry...'`)가 **수정 없이 그대로 통과**하는지(마크업을 안 건드렸으므로 당연히 통과해야 함 — 회귀 확인용), `.terms-hl`/`.terms-hl-num` span이 4곳에 정확히 존재하는지 검증.
- 애니메이션(타이틀 반복 등장, 하이라이트 스윕, reduced-motion)은 Playwright 라이브 검증.

## 자체 검토

- 플레이스홀더 스캔: 없음.
- 정직성/데이터 무결성: 표 숫자·문구 변경 없음 — 이번 스펙의 가장 중요한 제약.
- 내부 일관성: 개요 섹션의 반복-등장 패턴·이징 값을 그대로 재사용.
- 스코프: 타입&가격 섹션 하나, 별도 분해 불필요.
- 모호성: 강조 대상 4곳을 정확히 명시, 볼드 범위(첫 열만)를 명확히 함.
